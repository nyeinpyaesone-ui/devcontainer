## 🖥️ Interactive Bash Playground

### Overview
A fully interactive terminal emulator that lets you test bash commands in a simulated devcontainer environment. Perfect for validating commands before adding them to your setup scripts.

### Features
- **Real Terminal Emulation**: Full bash-like interface with prompt and command history
- **18 Pre-configured Commands**: Test common devcontainer commands instantly
- **Visual Feedback**: Color-coded output matching real terminal behavior
- **Command History**: Scroll through previous commands and outputs
- **Exit Code Display**: See command success/failure status

### Available Commands
```bash
# File system
ls, ls -la          # List directory contents
pwd                 # Print working directory

# System info
whoami              # Display current user
cat /etc/os-release # Show OS information
echo $SHELL         # Show current shell
echo $PATH          # Show PATH variable
df -h               # Show disk usage
free -h             # Show memory usage
ps aux              # Show running processes

# Tool versions
node --version      # Node.js version
npm --version       # npm version
git --version       # Git version
rustc --version     # Rust version
go version          # Go version
python --version    # Python version
docker --version    # Docker version

# Utilities
clear               # Clear terminal
help                # Show available commands
```

### Use Cases
- **Command Validation**: Test commands before adding to scripts
- **Learning Tool**: Explore devcontainer environment safely
- **Documentation**: Capture command outputs for documentation
- **Troubleshooting**: Debug environment issues interactively

### Access
Click the terminal icon (>_ ) in the header toolbar.

## 🎯 Visual Sprint Flowchart

### Overview
A beautiful visual representation of the 7-step sprint workflow, showing the progress and status of each phase in your devcontainer setup.

### Features
- **Visual Timeline**: See all 7 steps in a vertical flowchart
- **Status Indicators**: Color-coded status for each step
  - 🟢 Complete (green) - Step finished successfully
  - 🟡 Warning (yellow) - Step has issues to address
  - ⚪ Pending (gray) - Step not yet started
- **Smart Detection**: Automatically determines status based on configuration
- **Summary Statistics**: Quick overview of completion status

### The 7 Sprint Steps
1. **🚀 Initialize** - Set up repository structure
2. **⚙️ Configure** - Define devcontainer settings
3. **📦 Install** - Set up toolchains and packages
4. **✅ Validate** - Run security and lint checks
5. **🧪 Test** - Verify environment works
6. **📚 Document** - Generate documentation
7. **🎯 Deploy** - Ready for production

### Status Logic
- **Step 4 (Validate)**: Shows warning if non-root policy is disabled
- **Step 5 (Test)**: Shows pending if smoke test is disabled
- **Step 7 (Deploy)**: Shows pending if critical policies are disabled

### Use Cases
- **Progress Tracking**: See where you are in the setup process
- **Gap Identification**: Quickly spot incomplete steps
- **Team Communication**: Share visual status with team
- **Documentation**: Include in project documentation

### Access
Always visible in the right panel below the ship pipeline.

## 📝 Custom Lint Rules

### Overview
Create your own validation rules to enforce project-specific standards and best practices beyond the built-in checks.

### Features
- **Rule Builder**: Create custom rules with conditions
- **Condition Language**: Simple expression syntax
- **Severity Levels**: Error, Warning, or Info
- **Real-time Evaluation**: Rules evaluated against current config
- **Persistent Storage**: Rules saved to localStorage
- **Enable/Disable**: Toggle rules without deleting

### Condition Syntax
```javascript
// Node version check
nodeVersion >= 18

// Feature check
hasFeature('docker-in-docker')

// Port check
port == 3000

// Multiple conditions (future)
nodeVersion >= 18 && hasFeature('git')
```

### Example Rules
```javascript
// Rule 1: Ensure Node.js LTS
Name: Node Version Check
Condition: nodeVersion >= 18
Message: Consider using Node.js LTS version (18+)

// Rule 2: Check for Docker-in-Docker
Name: Docker in Docker
Condition: hasFeature('docker-in-docker')
Message: Docker-in-Docker is enabled for nested containers

// Rule 3: Verify specific port
Name: Web Server Port
Condition: port == 3000
Message: Web server should run on port 3000
```

### Rule Management
- **Add Rule**: Click "+ Add Rule" button
- **Edit Rule**: Currently read-only (delete and recreate)
- **Delete Rule**: Click trash icon
- **Toggle Rule**: Checkbox to enable/disable
- **View Results**: See pass/fail status for each rule

### Use Cases
- **Team Standards**: Enforce team-specific requirements
- **Project Rules**: Project-specific validation
- **Compliance**: Custom compliance checks
- **Best Practices**: Enforce organizational standards

### Access
Always visible in the right panel below the sprint flowchart.

## 📱 PWA (Progressive Web App) Support

### Overview
Install the forge as a standalone app on your device for offline access and native app-like experience.

### Features
- **Installable**: Add to home screen on mobile/desktop
- **Offline Support**: Works without internet connection
- **Service Worker**: Caches assets for offline use
- **App Manifest**: Proper PWA metadata
- **Standalone Mode**: Runs without browser UI
- **Theme Color**: Matches app branding

### Installation
**Desktop (Chrome/Edge)**:
1. Click the install icon in the address bar
2. Or: Menu → "Install GHCR Devcontainer Forge"
3. Click "Install" in the dialog

**Mobile (Android)**:
1. Open in Chrome
2. Tap menu (⋮) → "Add to Home screen"
3. Tap "Add"

**Mobile (iOS)**:
1. Open in Safari
2. Tap share button (□↑)
3. Tap "Add to Home Screen"
4. Tap "Add"

### PWA Features
- **App Icons**: 192x192 and 512x512 icons
- **Splash Screens**: Branded loading screens
- **Shortcuts**: Quick actions from app icon
  - New Configuration
  - Import Configuration
- **Offline Cache**: All assets cached for offline use
- **Auto-Update**: Service worker checks for updates

### Benefits
- **Fast Launch**: Opens like a native app
- **No Browser UI**: Full-screen experience
- **Offline Access**: Work without internet
- **Task Switching**: Appears in app switcher
- **Notifications**: Future push notification support

### Technical Details
- **Manifest**: `/manifest.json`
- **Service Worker**: `/sw.js`
- **Cache Strategy**: Cache-first with network fallback
- **Cache Name**: `devcontainer-forge-v2.2.0`
- **Cached Assets**: HTML, CSS, JS, manifest

### Use Cases
- **Mobile Development**: Configure on the go
- **Offline Work**: Work without internet
- **Quick Access**: Launch like a native app
- **Presentation**: Demo without browser distractions
